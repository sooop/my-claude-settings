# UI 모션

md-works(문서 편집기)와 jjokmae(PDF 쪽 정리 도구)에서 다듬은 값과 규칙이다. 목표는 화려함이 아니라 **무엇이 어디서 나타났고 어디로 갔는지 눈으로 따라갈 수 있게** 하는 것이다. 값을 요소마다 새로 고르면 화면마다 리듬이 달라져 조잡해 보이므로, 아래 표의 값만 쓰고 새 값을 만들지 않는다.

## 적용 방법

| 대상 | 방법 |
|---|---|
| 단일 HTML·아티팩트 | `assets/motion.css` 와 `assets/motion.js` 를 페이지에 인라인한다. `<style>/*__MOTION_CSS__*/</style>`, `<script>/*__MOTION_JS__*/</script>` 자리표시자를 두고 `node <이 스킬>/scripts/inline.mjs page.html` 을 실행한다. 내용을 읽어서 다시 타이핑하지 않는다(누락이 생긴다). |
| 번들러가 있는 바닐라·React·Vue 등 | 두 파일을 프로젝트에 `cp` 로 복사해 쓴다. `window.Motion` 전역이 싫으면 마지막 대입만 `export` 로 바꾼다. |
| Svelte 5 | `assets/motion.svelte.ts` 를 복사한다(`transition:popFx` 처럼 붙이는 md-works 구현). 맨 위의 `settings` import 와 `__ANIM__` 은 그 프로젝트의 설정 저장소·빌드 상수로 바꾼다. CSS 토큰은 `motion.css` 를 함께 쓴다. |
| TypeScript 로 끌어 놓기·재정렬을 직접 짜야 할 때 | `assets/ts/` 의 jjokmae 원본을 참고하거나 복사한다: `spring.ts`(스프링 풀이), `drag-ghost.ts`, `drag-session.ts`(제스처 수명), `page-flip.ts`·`plan.ts`(비행체 재정렬), `mode-flip.ts`(공유 요소 전환). 캔버스 썸네일을 전제로 한 부분은 대상에 맞게 고친다. |
| 이미 모션 라이브러리를 쓰는 프로젝트 | 라이브러리는 그대로 두고 아래 표의 값(길이·거리·배율·이징·스프링 상수)만 옮긴다. |

`assets/demo.html` 은 모든 효과를 한 화면에서 쓰는 견본이다. 호출 방법이 헷갈리면 이 파일을 읽는다. 브라우저에서 열면 눈으로 확인할 수 있다.

## 값

### 떠 있는 표면

기본 이징은 **ease-out** `cubic-bezier(0.2, 0.8, 0.2, 1)` 이다. 빠르게 출발해 길게 가라앉으므로 입력에 즉시 반응하면서 끝이 부드럽다. `ease-in-out`·`linear` 는 반응이 늦게 느껴져 등장·이동에 쓰지 않는다(무한 반복하는 진행 표시는 예외).

| 표면 | 열림 | 출발 상태 → 제자리 | 열림 이징 | 닫힘 | `Motion` kind |
|---|---|---|---|---|---|
| 툴팁 | 120ms | 위로 2px | ease-out | 90ms | `tip` |
| 팝오버·메뉴·컨텍스트 메뉴 | 260ms | 위로 4px, 배율 0.95 | 스프링 | 120ms, 위로 3px·배율 0.96 까지만 | `pop` |
| 모달 본체 | 400ms | 배율 0.95 | 스프링 | 130ms, 배율 0.97 까지만 | `modal` |
| 모달 배경(딤) | 400ms, **110ms 늦게 시작** | 투명 | ease-out | 140ms | `backdrop` |
| 사이드 패널·시트 | 220ms | 들어오는 쪽으로 40px | ease-out | 170ms | `panel-right`·`panel-left`·`panel-bottom` |
| 토스트 | 200ms | 아래로 8px | ease-out | 130ms, 아래로 4px 까지만 | `toast` |
| 화면 전체 안내(파일 놓기 등) | 220ms | 배율 0.985 | ease-out | 120ms | `overlay` |
| 목록 항목(여러 장이 한꺼번에 바뀜) | 220ms | 위로 6px, 배율 0.96 | ease-out | 165ms, 이동 없음 | `list` |
| 접기·펼치기 | 220ms | 높이·세로 여백 0 | ease-out | 200ms ease-in-out | `Motion.slide` |
| 색·테두리·그림자·눌림 | 130ms (`--dur-1`) | — | ease-out | 같음 | CSS |
| 위치·크기 전환(탭 밑줄 등) | 220ms (`--dur-2`) | — | ease-out | 같음 | CSS |

- 모든 등장은 투명도 0→1 을 함께 한다.
- **닫힘은 빠르게.** 열림의 절반 이하 길이로, ease-in `cubic-bezier(0.32, 0, 0.67, 0)` 으로 가속하며 빠지고, 열릴 때보다 덜 움직이며, 튀지 않는다. 닫기는 사용자가 이미 다음 일로 넘어간 뒤라, 열림만큼 길면 굼뜨고 다음 조작을 가로막는 것처럼 느껴진다. 동작 줄이기에서는 90ms 페이드.
- 스프링은 **나타날 때**, **크기가 변하는 표면**에만 쓴다. 사라질 때 튀면 닫기가 느려 보이고, 이동만 하는 요소가 튀면 흔들려 보인다.
- 팝오버·메뉴는 **앵커 쪽 모서리에서 자라난다.** `transform-origin` 을 앵커에 가까운 모서리로 둔다(단추 아래로 열리면 `top left`, 위로 뒤집히면 `bottom left`). 가운데에서 커지면 어디서 나왔는지 끊긴다.
- 배경을 늦게 어둡게 하는 이유: 본체와 배경이 동시에 바뀌면 화면 전체가 번쩍인다. 본체가 먼저 움직이면 시선이 본체에 붙는다.

### 성격별 스프링

물체가 크거나 멀리 움직이면, 또는 사용자가 직접 잡고 있으면 ease-out 하나로는 무게가 표현되지 않는다. 그때는 물리 스프링 다섯 가지 중에서 고른다. 길이는 고르는 값이 아니라 스프링이 가라앉는 시간에서 나온다.

| 이름 | k / c | 길이 | 성격 | 쓰는 곳 |
|---|---|---|---|---|
| `pop` | 620 / 30 | 396ms | 빠르게 도착해 한 번 살짝 넘친다(약 9%) | 삽입 선이 자리 사이를 건너감, 고스트 그림자, 호버 단추 줄 |
| `bouncy` | 420 / 19 | 604ms | 통통 튄다(약 19%) | 체크·선택 표시, 개수 배지, 받는 반응(pulse), 부채꼴 |
| `glide` | 260 / 27 | 504ms | 미끄러지고 거의 넘치지 않는다 | 카드·썸네일의 자리 이동, 선택 표시(잉크)의 이동, 벌어지는 칸 |
| `heavy` | 210 / 29 | 587ms | 넘침 없이 묵직하다 | 넓은 서랍, 화면 전환의 공유 요소 |
| `snappy` | 700 / 38 | 283ms | 짧고 단단하다 | 눌림에서 돌아옴, 작은 반응 |

CSS 에서는 `transition: transform var(--spring-glide-dur) var(--spring-glide)`, JS 에서는 `Motion.springOf('glide')` 가 `{ duration, css }` 를 준다.

**어느 쪽을 쓰나**: 목록 행처럼 작고 가까운 이동은 ease-out 220ms(`Motion.flip` 기본). 카드·썸네일처럼 크거나 화면을 가로지르는 이동은 `glide`(`Motion.flip(c, fn, null, 'glide')`). 같은 화면에서 둘을 섞지 않는다.

## 규칙

1. **사라짐도 만든다.** 닫을 때 `display: none` 으로 바로 지우면 열림만 부드럽고 닫힘은 뚝 끊긴다. `Motion.leave(el, kind, after)` 가 끝난 뒤에 숨기거나 제거한다. `<dialog>` 는 `Motion.dialog.open/close` 를 쓴다(Esc 와 배경 클릭도 같은 사라짐을 거친다).
2. **조작은 연출을 기다리지 않는다.** 데이터는 즉시 바꾸고 연출은 그 위에서 돈다. 전환 도중에도 입력을 받는다. 연출 중에 다음 조작이 오면 앞의 것을 즉시 끝 상태로 보내고 이어받는다.
3. **끄기 스위치를 처음부터 둔다.** `<html data-anim="off">` 이면 CSS 길이 토큰이 0 이 되고 JS 효과는 즉시 끝난다. 설정이 있는 앱이면 "애니메이션" 토글을 이 속성에 연결한다. 효과를 직접 만들 때도 `Motion.on()` 을 먼저 본다.
4. **동작 줄이기(`prefers-reduced-motion`)에서는 이동·확대·스프링을 빼고 짧은 페이드만 남긴다.** 통째로 끄면 변화가 있었다는 신호까지 사라진다. 끌기 고스트처럼 기능 정보인 것은 연출 없이 남긴다. `motion.css` 끝의 안전망이 손으로 쓴 CSS 전환까지 끈다(전환은 `0s`, 키프레임은 `0.01ms`: 이유는 그 주석에 있다).
5. **`transform`·`opacity` 만 움직인다.** 위치를 `transform: translate(-50%, …)` 로 잡은 요소에는 개별 속성 `translate`·`scale` 을 쓴다(덮어쓰면 재생 중에 위치가 튄다). `will-change` 는 지금 움직이는 요소에만 준다.
6. **`transition: all` 을 쓰지 않는다.** 바뀌는 속성만 나열한다. 레이아웃 속성까지 전환되어 버벅이고, 테마 전환 때 온 화면이 흐물거린다.
7. **눌림은 작은 단추에만.** 아이콘 단추 0.92, 주 단추 0.97, 체크박스 0.88. 목록 행·메뉴 항목처럼 넓은 요소가 줄어들면 어색하다.
8. **대상 수에 상한을 둔다.** 자리 이동(FLIP)은 80개, 비행체는 70개까지. 보이지 않는 항목은 다루지 않는다.
9. **처음 그릴 때는 재생하지 않는다.** 삽입·등장 효과는 사용자의 조작으로 생긴 변화에만 쓴다. 본문·탭 내용의 교체는 이동 없는 `mo-soft-in` 페이드로 충분하다.
10. **무한 반복은 진행 중임을 알릴 때만.** 스피너, 진행 막대, 파일을 놓으라는 안내 아이콘의 흔들림 정도.
11. **호버로 레이아웃을 바꾸지 않는다.** 호버는 색·그림자만. 크기나 위치가 바뀌면 포인터 아래 요소가 달아나 깜빡인다.
12. **숨긴 것은 반드시 되돌린다.** 연출을 위해 실제 요소를 가렸으면, 연출이 끝나지 않는 경우(실패, 탭 숨김)에도 풀리도록 시한을 건다.

## 상태 변화를 알리기

사용자가 누른 단추 때문에 **다른 곳**의 내용이 자동으로 바뀌면, 바뀐 영역을 의미색으로 한 번 비춘다(900ms: 12% 지점까지 밝아짐 → 35% 까지 유지 → 사라짐, 불투명도 17% 의 면 + 1px 테두리).

| 일어난 일 | flash 액션 | 색 토큰 |
|---|---|---|
| 구조 변환(목록↔표 등) | `convert` | `--fx-info` |
| 삽입·생성·붙여넣기 | `insert` | `--fx-success` |
| 자동 정리·보정·정렬 | `tidy` | `--fx-accent` |
| 충돌·경고 | `conflict` | `--fx-warn` |
| 삭제·되돌림 | `remove` | `--fx-danger` |

- `Motion.flash(target, action)`: 요소 위에 상자를 겹쳐 띄우고 치운다. 요소 자체의 스타일을 건드리지 않으므로 에디터처럼 DOM 을 다시 그리는 영역에도 안전하다.
- `Motion.insert(el)`: ① 4px 내려오며 나타남(260ms) → ② success flash. 나타나기 전에 비추면 무엇이 생겼는지 보이지 않는다.
- `Motion.remove(el)`: ① danger flash 로 **무엇이 지워지는지 먼저** 알림(600ms) → ② 오른쪽으로 8px 밀리며 흐려지고 자리가 접힘(190ms) → DOM 에서 제거.
- `Motion.flip(container, mutate)`: `mutate` 안에서 자식의 순서·구성을 바꾸면 남은 항목이 미끄러져 자리를 잡는다. 정렬, 필터, 토스트 쌓임에 쓴다.
- `Motion.pulse(el)`: **받는 반응.** 무언가를 받은 대상(항목이 들어간 폴더·탭, 숫자가 바뀐 배지)이 한 번 튕기고 고리가 퍼진다. 보내는 쪽만 움직이고 받는 쪽이 가만히 있으면 항목이 그냥 사라진 것처럼 보인다.
- **선택 표시는 옮겨 간다.** 탭·목록의 선택 배경을 항목마다 켜고 끄지 않고, 표시 하나(`.mo-ink`)가 `glide` 로 미끄러져 새 항목으로 간다. 처음 그릴 때는 전환 없이 제자리에 둔다.
- **되돌리기는 같은 연출을 거꾸로.** 되돌렸는데 화면이 뚝 바뀌면 무엇이 되돌아갔는지 알 수 없다.
- 사용자가 직접 입력한 자리(타이핑한 글자, 방금 누른 토글)에는 flash 를 쓰지 않는다. 이미 보고 있는 곳이다.

## 끌어서 놓기

끌어 놓기가 고급스럽게 보이는 것은 장식 때문이 아니라 **항목이 한 번도 사라지거나 순간이동하지 않고, 손에 든 것에 무게가 있기** 때문이다. 다음 순서를 지킨다. 직접 구현할 때의 값·예외 처리·성능은 `references/drag.md` 에 있다.

1. **집기.** 4~5px 이상 움직였을 때 끌기로 본다(그 전에는 클릭). 고스트가 그림자를 얻고 배율 1.045 로 떠오른다. 잡은 지점이 포인터 아래에 그대로 있어야 한다.
2. **따라오기.** 고스트는 포인터에 붙지 않고 **스프링으로 따라오며, 가로 속도에 비례해 기운다**(최대 ±13°, 넓은 행은 ±2.5°). 멈추면 돌아온다.
3. **여러 개.** 최대 4장이 부채꼴로 차례로 벌어지고 개수 배지가 튀어나온다. 집은 것 외의 원본은 목록에서 빠진다.
4. **원래 자리.** 끌던 항목의 자리는 빈 슬롯이나 흐린 자리표시로 바뀐다. 멀쩡한 원본이 남아 있으면 같은 항목이 두 곳에 있는 것처럼 보인다.
5. **놓일 자리.** 세로 목록·트리는 한 행 높이의 **빈 슬롯**(`--accent-soft` 면 + 점선)을 열고 이웃이 비킨다. 격자·가로 띠처럼 슬롯이 줄바꿈을 흔드는 배치는 **삽입 선** + 양옆 칸이 12px 벌어짐. 폴더 같은 그릇 **안으로**는 그릇 자체를 강조한다.
6. **놓을 수 있는 곳이 드러난다.** 끌기가 시작되면 바깥 대상(다른 탭·목록·새로 만들기 칸)에 점선 테두리가 생긴다. 그 위에 올라가면 대상이 채워지고 고스트는 절반으로 줄어든다.
7. **깜빡임 막기.** 자리 표시는 행 사이를 지날 때 거두지 않고 하나의 표시를 옮긴다. 이웃을 넘었는지는 미끄러지는 중인 화면 위치가 아니라 레이아웃상의 자리로 판정한다.
8. **설명은 필요할 때만.** 자리 표시만으로 결과를 알 수 없을 때(다른 그릇으로 감, 복사인지 이동인지, 놓을 수 없는 이유) 고스트 아래 띠나 목록 아래 한 줄로 말한다. 보조 키(Shift)로 결과가 바뀌면 놓기 전에 띠가 바뀐다.
9. **가장자리 스크롤, 머무르면 열기.** 목록 끝 48px 안에서는 저절로 스크롤된다. 접힌 그릇 위에 700ms 머물면 펼친다.
10. **착지.** 고스트가 **놓은 지점에서** 들어갈 자리로 내려앉는다(원래 자리에서 출발시키지 않는다). 실제 항목은 그때까지 숨겼다가 드러낸다. 그릇 안으로는 **빨려 들어가고**(느리게 출발해 급가속하며 작아짐) 그릇이 `pulse` 로 받는다.
11. **옮기기는 삭제+삽입이 아니다.** 이동으로 생긴 DOM 변화에는 삽입·삭제 flash 를 재생하지 않는다. 고스트의 비행이 그 역할을 한다.
12. **취소·유실·대체 수단.** Esc 는 취소이며 고스트가 원래 자리로 돌아간다. 창 포커스 이동, 탭 숨김, 창 밖에서 놓아 신호를 놓친 경우도 취소로 끝낸다(고스트가 화면에 남는 결함의 원인이다). 끄는 사이 데이터가 바뀌었으면 옮기지 않는다. 키보드로 같은 일을 할 수 있게 한다(Alt+↑/↓).

`Motion.sortable(list, opts)` 가 한 줄 세로 목록에 대해 위 전부를 구현한다(포인터 이벤트 기반이라 터치 공통, 손잡이에는 `touch-action: none`). 트리, 격자, 여러 목록 사이의 이동은 `Motion.dragGhost`·`Motion.flip`·`Motion.pulse` 와 `.mo-slot`·`.mo-drop-line`·`.mo-part` 를 조합해 직접 구현한다. HTML5 드래그 API(`draggable`)를 써야 하면(파일·다른 창과 주고받기) 브라우저가 고스트를 그리므로 스프링 고스트는 쓸 수 없고, 끌기 시작 때 복제본을 보관해 두었다가 `drop` 에서 `Motion.flyGhost` 로 날린다.

## 화면이 통째로 다시 그려질 때

요소를 직접 미끄러뜨리는 FLIP 은 같은 DOM 요소가 살아남을 때만 된다. 가상 스크롤, 캔버스 썸네일, 서버에서 다시 받는 목록처럼 구조가 바뀌면 목록이 다시 만들어지는 경우와, 두 화면이 같은 대상을 다른 크기로 보여 주는 화면 전환(목록 ↔ 상세, 보기 ↔ 정리)에서는 **비행체**를 쓴다. 조작 직전에 보이는 항목의 모습을 복사해 위 층에 띄우고, 새 자리로 스프링으로 옮긴 뒤, 새 화면이 그려지면 넘겨 준다. 절차와 값은 `references/drag.md` 의 6·7절, 구현은 `assets/ts/page-flip.ts`·`mode-flip.ts`.

View Transitions API 는 전환하는 동안 실제 화면이 입력을 받지 못하므로, 전환 중에도 조작이 이어져야 하는 곳에는 쓰지 않는다.

## `Motion` 요약

```js
Motion.enter(el, 'pop');                              // 보이게 한 직후 호출
Motion.leave(el, 'pop', () => (el.hidden = true));    // 끝난 뒤 숨김. 세 번째 인자를 생략하면 DOM 에서 제거
Motion.dialog.open(dlg);  Motion.dialog.close(dlg);   // <dialog> + ::backdrop
Motion.slide(el, open);                               // hidden 속성을 함께 관리
Motion.flash(elOrRect, 'convert');
Motion.insert(el);  Motion.remove(el);                // remove 는 끝나면 el 을 제거한다
Motion.flip(container, () => { /* 자식 순서·구성 변경 */ });        // 네 번째 인자 'glide' 로 큰 물체용 스프링
Motion.pulse(target);                                 // 받는 반응
Motion.springOf('glide');                             // { duration, css } → el.animate(..., { duration, easing: css })
Motion.sortable(list, {
  handle: '.grip',
  group: (item) => selectedEls,                       // 함께 끌 항목들(선택)
  label: (items, target) => (target ? `${target.dataset.name} 로 이동` : ''),
  onMove: ({ item, items, from, to }) => {},
  onDropInto: ({ items, target }) => {},              // 목록 밖 [data-mo-drop] 에 놓음
});
const g = Motion.dragGhost({ items, pointer: { x, y }, label });   // 직접 구현할 때
g.move(x, y);  g.setInto(true);  g.setLabel('…');  await g.land(rect);  // 또는 g.into(target), g.cancel()
```

모두 Promise 를 돌려준다. 닫히는 도중 다시 열면 앞의 효과를 거두고 새 효과가 이어받는다.

## 서브 에이전트에 맡길 때

UI 를 만드는 작업을 위임하면 지시문에 다음을 넣는다. 값을 지시문에 옮겨 적지 말고 파일을 가리킨다.

```
움직임은 ~/.claude/skills/ui-motion/SKILL.md 의 정책을 따른다. 먼저 그 파일을 읽는다.
끌어 놓기·재정렬·화면 전환을 직접 구현하면 references/drag.md 도 읽는다.
- assets/motion.css·motion.js(Svelte 면 motion.svelte.ts)를 cp 로 가져와 쓰고, 길이·이징·거리·스프링 값을 새로 만들지 않는다.
- 떠 있는 표면(팝오버·메뉴·모달·패널·토스트)은 모두 나타남과 사라짐을 갖는다.
- 목록의 추가·삭제·순서 변경은 insert·remove·flip 을 거친다.
- 끌어 놓기는 '끌어서 놓기' 절의 12단계를 모두 갖춘다. 빠뜨린 단계가 있으면 이유를 보고한다.
- <html data-anim="off"> 과 prefers-reduced-motion 에서의 동작을 유지한다.
끝나면 '마무리 점검' 항목별로 어떻게 처리했는지 보고한다.
```

## 마무리 점검

- 열리는 모든 표면이 닫힐 때도 사라지는가(Esc·바깥 클릭·단추 모두). 닫힘이 열림보다 짧은가.
- 표에 없는 길이·이징 값이 코드에 생기지 않았는가(`rg 'cubic-bezier|[0-9]+ms|transition: all'` 로 확인).
- `data-anim="off"` 에서 모든 것이 즉시 끝나고, 닫힌 요소가 화면에 남지 않는가.
- 동작 줄이기에서 이동·확대 없이 페이드만 남는가.
- 삭제가 무엇을 지우는지 먼저 보여 주는가. 추가된 항목이 어디에 생겼는지 보이는가. 받는 쪽이 반응하는가.
- 끌어 놓기: 고스트가 잡은 지점을 유지하는가, 놓일 자리가 보이는가, 놓은 지점에서 착지하는가, Esc·창 포커스 이동으로 취소되는가, 키보드 대체 수단이 있는가.
- 놓기·취소·바깥 대상에 놓기 뒤에 고스트·비행체·자리표시 클래스(`.mo-drag-ghost`, `.mo-slot`, `.mo-drag-away`, `.mo-drop-over`, `html.mo-dragging`)가 DOM 에 남지 않는가.
- 빠르게 연타(열기→닫기→열기, 연속 재정렬)해도 상태가 꼬이지 않는가. 연출 도중에 입력을 받는가.
