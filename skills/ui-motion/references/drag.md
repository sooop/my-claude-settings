# 끌어 놓기와 구조 변경 연출: 상세

SKILL.md 의 끌어 놓기 절을 직접 구현해야 할 때(트리, 격자, 여러 목록·패널 사이의 이동, 화면이 통째로 다시 그려지는 앱) 읽는다. 한 줄 세로 목록은 `Motion.sortable` 로 끝난다.

## 차례

1. 제스처 수명: 누름 → 문턱 → 끌기 → 놓기·취소·중단
2. 고스트
3. 놓일 자리 표시: 슬롯과 선
4. 바깥 대상에 놓기
5. 착지
6. 비행체: 다시 그려지는 화면에서의 자리 이동
7. 공유 요소 전환
8. 성능
9. 시험

## 1. 제스처 수명

끌어 놓기의 결함은 대부분 연출이 아니라 **끝나지 않은 제스처**에서 나온다. 고스트가 화면에 남거나, 슬롯이 열린 채 굳거나, 숨겨 둔 항목이 돌아오지 않는다. 수명 관리를 한 곳(세션 객체)에 모으고 컴포넌트는 삽입 자리 계산만 맡는다. 원본 구현은 `assets/ts/drag-session.ts`.

| 단계 | 할 일 |
|---|---|
| 누름 | 포인터 id 를 기억한다. 마우스는 주 단추만. 터치는 손잡이에서만 시작한다(항목 전체는 스크롤에 양보: 항목 `touch-action: pan-y`, 손잡이 `touch-action: none`). `window` 에 move·up·cancel·keydown 을 건다 |
| 문턱 | 4~5px 움직이기 전에는 클릭이다. 손잡이를 잡았으면 문턱 없이 바로 시작해도 된다. 길게 누르기 메뉴가 있으면 8px 넘게 움직일 때 그 타이머를 지운다 |
| 끌기 | 다른 포인터 id 의 이벤트는 무시한다. `preventDefault` 로 글자 선택·스크롤을 막는다. 프레임마다 가장자리 자동 스크롤을 돌린다(포인터가 멈춰 있어도 굴러야 한다). 스크롤이 움직이면 삽입 자리를 다시 계산한다 |
| 놓기 | 삽입 자리를 **끝내기 전에** 읽어 둔다(정리하면 사라진다). 고스트의 현재 사각형을 넘겨받아 착지 연출이 그 자리에서 출발하게 한다. 끌기 끝의 `click` 한 번을 막는다 |
| 취소 | Esc, `pointercancel`, 창 `blur`, 탭 숨김(`visibilitychange`), 마우스 `pointermove` 인데 `buttons === 0`(창 밖에서 놓아 up 을 놓친 경우). 고스트가 원래 자리로 돌아가는 동안 원본은 자리표시 상태로 둔다 |
| 중단 | 끄는 사이 데이터가 바뀌었다(되돌리기, 원격 갱신, 다른 탭의 변경). 누를 때 상태 식별값을 기억해 두고, 놓을 때 다르면 **옮기지 않고** 고스트를 바로 치운다. 처음 집은 번호로 엉뚱한 항목을 옮기는 것보다 아무 일도 하지 않는 편이 안전하다 |
| 파괴 | 컴포넌트가 사라질 때 리스너·프레임·고스트를 모두 정리한다. 부모 상태는 건드리지 않는다 |

끄는 동안에는 구조를 바꾸는 단축키(되돌리기, 삭제, 탭 전환)를 무시한다. 전역 "제스처 진행 중" 표시를 두고 단축키 처리기가 그것을 본다.

## 2. 고스트

`Motion.dragGhost` (원본: `assets/ts/drag-ghost.ts`).

- **스프링으로 따라온다.** 포인터 좌표에 고스트를 직접 붙이지 않고, 포인터를 목표로 하는 스프링(k 520, c 36)으로 따라가게 한다. 약간 뒤처졌다가 따라붙는 것이 무게로 읽힌다. 뒤처짐은 한두 프레임 수준이어야 하며 더 무르면 조작이 둔해진다.
- **떠오른다.** 집는 순간 배율 1.045(넓은 행은 1.02)로 커지고 깊은 그림자가 생긴다. 한 장이면 -2.5° 로 살짝 기운 채 쉰다.
- **속도에 기운다.** 가로 속도 × 0.011° (최대 ±13°, 넓은 행은 ±2.5°). 오른쪽으로 빠르게 끌면 시계 방향으로 눕는다. 멈추면 스프링으로 돌아온다.
- **여러 개는 부채꼴.** 최대 4장이 40ms 간격으로 차례로 벌어지고(각 5.5°·-4.5°·10°), 오른쪽 위에 개수 배지가 튀어나온다(bouncy, 90ms 지연). 5개를 끌어도 카드는 4장이고 배지가 5 를 말한다.
- **설명 띠.** 고스트 아래 가운데에 지금 놓으면 일어날 일을 한 구절로 적는다("3쪽 이동", "보고서.pdf 로 복사 · Shift 이동"). 보조 키(Shift)를 누르거나 떼면 놓기 전에 바로 바뀐다. 슬롯만으로 결과가 분명하면 비워 둔다.
- **잡은 지점이 원점.** 배율·기울기의 `transform-origin` 을 잡은 지점에 두어야 커지거나 기울 때 포인터 아래에서 미끄러지지 않는다.
- **이미 그린 것을 복사한다.** 캔버스 썸네일은 비트맵을 `drawImage` 로 복사한다(다시 렌더하지 않는다). 큰 요소는 처음부터 줄인 크기(최대 300px)로 만들고 변환 배율로 원래 크기를 보인다. 전체 크기의 합성 레이어를 만들지 않기 위해서다.
- **위치는 transform 만.** 배지·설명 띠도 `left/top` 이 아니라 transform 으로 옮긴다.
- **동작 줄이기.** 스프링·기울기·부채꼴 연출 없이 포인터에 바로 붙는다. 고스트 자체는 남긴다(무엇을 끌고 있는지는 기능 정보다).

## 3. 놓일 자리 표시: 슬롯과 선

| 배치 | 표시 | 이유 |
|---|---|---|
| 세로 목록·트리(행이 낮다) | **빈 슬롯**: 한 행 높이가 열리고 이웃이 미끄러져 비킨다 | 놓은 뒤의 모습을 그대로 보여 준다. 행 하나만큼 밀리는 비용이 작다 |
| 격자·가로 띠·가상 스크롤(칸이 크다) | **삽입 선** + 양옆 칸이 12px 씩 벌어짐 | 슬롯을 열면 줄바꿈이 연쇄로 일어나 화면 전체가 요동친다 |
| 그릇(폴더·탭·다른 목록) 안으로 | 그릇 자체를 강조 | 안에서의 위치는 정해지지 않는다 |

- 삽입 선은 하나의 요소를 `transform` 으로 옮긴다. 자리가 바뀌면 선이 스프링(pop)으로 건너가므로 깜빡이지 않는다(`.mo-drop-line`).
- 벌어지는 칸에는 glide 스프링 전환을 건다(`.mo-part`). 끌기가 끝나면 전환 클래스도 함께 뗀다.
- 삽입 자리는 포인터 좌표와 **레이아웃상의 칸 배치**로 계산한다. 미끄러지는 중인 화면 위치로 판정하면 두 칸이 서로 자리를 뺏으며 떤다.
- 끄는 동안에는 칸 위의 호버 단추·손잡이를 숨긴다. 포인터가 지나갈 때마다 켜지면 산만하다.
- 끌던 원본은 자리표시(흐리게 또는 슬롯)로 두고, 취소로 고스트가 돌아오는 동안에도 그 상태를 유지한다.

## 4. 바깥 대상에 놓기

끌기가 시작되면 **놓을 수 있는 곳이 스스로 드러나야** 한다. 사용자는 어디에 놓을 수 있는지 끌어 보기 전에는 모른다.

- 끄는 동안 놓을 수 있는 대상(다른 탭, 파일 목록 항목, "새로 만들기" 칸)에 점선 테두리를 준다. 놓을 수 없는 것(자기 자신)은 흐리게 한다.
- 포인터 아래 대상은 `document.elementFromPoint` 로 찾는다(고스트는 `pointer-events: none`). 대상 위에 올라가면 대상은 채워지고, 고스트는 배율 0.5 로 줄어든다. "이 안으로 들어간다"는 뜻이다. 가장자리 자동 스크롤은 멈춘다.
- 놓으면 고스트가 대상으로 **빨려 들어간다**: 14px 떠올랐다가(22% 지점) 느리게 출발해 급격히 가속하며(`cubic-bezier(0.55, 0, 0.85, 0.35)`) 작아지고 흐려진다. 여러 장이면 55ms 간격으로 차례로.
- 도착하면 대상이 **받는 반응**을 보인다: 한 번 튕기고(bouncy, 배율 1.05~1.08) 고리가 퍼진다(`Motion.pulse`). 받는 쪽이 반응하지 않으면 항목이 그냥 사라진 것처럼 보인다.
- 복사인지 이동인지는 설명 띠가 말한다. 복사면 원본은 그대로 두고, 이동이면 빨려 들어간 뒤 원본 삭제 연출이 이어진다.

## 5. 착지

- 고스트는 **놓은 지점에서** 들어갈 자리로 간다. 원래 자리에서 출발시키지 않는다.
- 스프링으로 내려앉으며 배율 1, 기울기 0 으로 돌아오고 부채꼴이 접힌다. 가까워지면(1.2px 이내, 속도 20px/s 미만) 끝낸다. 650ms 가 넘으면 기다리지 않는다.
- 실제 항목은 고스트가 앉을 때까지 숨겼다가 그 순간 드러낸다. 비동기로 그려지면(서버 응답, 다시 렌더) 나타나는 즉시 숨기고, 고스트가 앉은 뒤 140~180ms 로 넘겨 준다.
- **조작은 연출을 기다리지 않는다.** 놓는 즉시 데이터를 바꾸고 연출은 그 위에서 돈다. 연출이 끝나야 다음 조작을 받는 UI 는 느리다.
- **연속 조작은 이어받는다.** 앞의 연출이 도는 중에 다음 조작이 오면 앞의 것을 즉시 끝 상태로 보내고 새 연출을 시작한다.
- **안전장치를 둔다.** 연출이 어떤 이유로 끝나지 않아도(조작 실패, 탭 숨김, 요소 제거) 숨겨 둔 항목이 계속 가려져 있지 않도록 시한(2.5~5초)을 건다.

## 6. 비행체: 다시 그려지는 화면에서의 자리 이동

FLIP 은 같은 DOM 요소가 살아남을 때만 쓸 수 있다. 구조가 바뀌면 목록이 통째로 다시 만들어지는 앱(가상 스크롤, 캔버스 썸네일, 서버에서 다시 받는 목록)에서는 요소를 직접 움직일 수 없다. 원본 구현: `assets/ts/page-flip.ts`, `assets/ts/plan.ts`.

1. 조작 직전, **보이는 항목만** 복사한 비행체를 목록 위 층(`position: absolute`, 내용 좌표계)에 띄운다. 화면 밖 항목은 다루지 않는다(여유 40px, 최대 70개).
2. 조작을 "이전 번호 → 이후 번호"의 **계획**으로 표현한다(재정렬·삭제·복제·회전). 목적지는 배치 산술로 미리 알 수 있으므로 비행체는 조작이 끝나길 기다리지 않고 바로 출발한다.
3. 실제 칸은 가려 둔다. 비행체가 내려앉고 새 화면이 그려지면 비행체를 180ms 로 흐리며 넘겨 준다. 새 칸이 그려지기 전에 넘기면 빈 칸이 번쩍인다.
4. 자리가 그대로인 항목은 움직이지 않는 정지 비행체로 둔다(애니메이션·레이어를 만들지 않는다).

| 일 | 연출 |
|---|---|
| 이동 | glide 스프링. 항목마다 7ms 씩 늦게 출발(최대 90ms). 끌어 놓은 항목은 지연 없이 고스트 자리에서 출발하고 그림자를 유지한다 |
| 사라짐 | 240ms ease-in: 10px 떠오르며 배율 0.55 로 줄고 흐려진다 |
| 생김 | 배율 0.8 에서 자라며 나타난다. 복제는 원본 자리에서 갈라져 나온다 |
| 회전 | 이동과 같은 스프링으로 각도·배율을 한 번에 보간한다 |

**되돌리기는 같은 연출을 거꾸로 재생한다.** 계획을 조작 전후의 상태 id 에 묶어 기록해 두고, 되돌리기·다시하기 때 뒤집어 쓴다. 되돌렸는데 화면이 뚝 바뀌면 무엇이 되돌아갔는지 알 수 없다.

## 7. 공유 요소 전환

두 화면(보기 ↔ 정리, 목록 ↔ 상세)이 같은 대상을 다른 크기·자리에 보여 주면, 옛 화면의 요소가 새 화면의 자리로 이어지게 한다. 원본: `assets/ts/mode-flip.ts`.

- 전환 **직전**에 보이는 요소의 사각형과 모습(비트맵·복제본)을 잡아 둔다. 옛 화면은 곧 사라진다. 최대 16개.
- 새 화면이 그려진 뒤, `position: fixed` 층의 비행체를 같은 식별자의 새 자리로 heavy 스프링으로 옮긴다(14ms 씩 늦게, 최대 100ms). 새 요소는 그동안 투명하게 두었다가 140ms 로 드러낸다.
- 새 화면에 짝이 없으면 제자리에서 배율 0.85 로 줄며 사라진다(220ms ease-in).
- View Transitions API 는 전환하는 동안 실제 화면이 입력을 받지 못한다. 전환 중에도 바로 조작할 수 있어야 하면 비행체 방식을 쓴다.

## 8. 성능

- 움직이는 속성은 `transform`·`opacity` 뿐이다. 높이를 접는 슬라이드처럼 레이아웃 속성이 필요한 경우는 짧고(220ms) 작은 영역에만 쓴다.
- `will-change: transform` 은 지금 움직이는 요소(고스트, 비행체)에만 주고 끝나면 요소째 치운다. 목록 전체에 걸어 두지 않는다.
- 연출 대상에 상한을 둔다(비행체 70, 공유 요소 16, 빨려 들어가는 카드 12, 부채꼴 4, FLIP 80). 보이지 않는 것은 다루지 않는다.
- 프레임 루프는 끌기 동안만 돌리고 끝나면 `cancelAnimationFrame` 한다. 스프링 적분은 프레임 간격이 길어져도 발산하지 않게 1/120초 이하로 쪼갠다(프레임 간격 상한 50ms).
- 값을 끌어 조절하는 컨트롤(확대 슬라이더 등)은 끄는 동안 CSS 변환으로 즉시 따라가고, 멈췄을 때 비싼 작업(다시 렌더, 저장)을 확정한다.

## 9. 시험

모션은 눈으로만 확인하면 회귀를 놓친다. e2e 에서 다음을 단언한다(원본: jjokmae `app/e2e/motion.spec.ts`, `ghost.spec.ts`).

- 끌면 고스트가 생기고(카드 수, 배지 숫자), 놓기·Esc·바깥 대상에 놓기 뒤에는 **고스트·비행체·자리표시 클래스가 DOM 에 남지 않는다**.
- Esc 뒤 순서와 되돌리기 기록이 그대로다.
- 열리는 표면은 열릴 때 실행 중인 애니메이션을 가진다(`el.getAnimations().length > 0`).
- 동작 줄이기(`emulateMedia({ reducedMotion: 'reduce' })`)에서 비행체가 생기지 않고 조작 결과는 같다.
- 전환 도중에도 입력을 받는다.

`assets/demo.html?selftest` 가 `Motion` 에 대한 같은 종류의 점검을 한다.
