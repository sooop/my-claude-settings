# 기존 화면 감사

이미 만들어진 화면을 [SKILL.md](../SKILL.md) 의 규칙에 대조할 때 읽는다. 규칙의 원본은 SKILL.md 이고, 이 문서는 대조하는 절차와 심각도, 확인 방법, 보고 형식만 정한다.

감사 중에는 고치지 않는다. 고치는 일은 보고를 본 사용자가 범위를 정한 뒤에 한다.

## 절차

1. **범위를 정한다.** 화면 전체인지, 특정 화면·부품인지, 최근 변경분인지 정한다. 지시에 없으면 묻는다. 범위가 넓으면 화면 단위로 나눠 병렬로 본다.
2. **의도된 예외를 모은다.** 프로젝트의 규칙 문서(`AGENTS.md`, `CLAUDE.md`, `DESIGN.md`, README)와 코드 주석에서 이 스킬과 다르게 정한 결정을 찾는다. 문서로 정한 결정은 결함으로 세지 않고 "의도된 예외"에 따로 적는다. 그 결정 때문에 사용자가 실제로 막히는 경우(예: 설명을 호버에만 두어 터치에서 볼 수 없음)는 영향을 함께 적는다.
3. **있는 부품을 적는다.** 모달, 서랍, 메뉴, 탭, 목록, 데이터 표, 분할선, 파일 드롭, 자동 실행이 있는지 본다. 없는 부품의 규칙은 "해당 없음"이다.
4. **검색으로 찾는다.** 아래 표의 패턴으로 후보를 모으고, 후보마다 코드를 읽어 맞는지 확인한다. 검색 결과를 그대로 발견으로 세지 않는다.
5. **화면에서 확인한다.** 앱을 띄울 수 있으면 아래 "직접 해 볼 조작"을 한다. 띄울 수 없으면 코드로 추적하고, 그 발견의 확인 수준을 "코드만 읽음"으로 적는다. 개발 서버를 임의로 띄우지 않는다. 프로젝트 규칙을 따른다.
6. **원인별로 묶는다.** 같은 원인에서 나온 발견은 하나로 묶는다. 모달 아홉 개가 저마다 Esc 를 처리한다면 발견은 "공용 모달 수단이 없음" 하나이고 아홉 곳은 그 위치 목록이다. 묶음마다 고치는 방법이 하나여야 한다.
7. **보고한다.** 아래 형식을 따른다.

## 심각도

| 단계 | 뜻 | 예 |
|---|---|---|
| 잃음 | 사용자의 작업물이나 데이터가 사라지거나, 되돌릴 수 없는 일이 뜻하지 않게 실행된다 | 새로 고침·샘플 불러오기로 입력이 사라짐, 영구 삭제 확인창의 포커스가 확정 단추에 있음, 입력 중인 모달이 바깥 클릭으로 닫힘 |
| 막힘 | 어떤 사용자는 기능에 닿지 못하거나 엉뚱한 동작이 난다 | 키보드로 열 수 없는 메뉴, 한글 조합 중 Enter 가 확정으로 처리됨, 터치에서 보이지 않는 호버 전용 단추, 포커스가 창 밖으로 나감, 겹친 창이 Esc 한 번에 모두 닫힘 |
| 틀림 | 닿을 수는 있지만 화면이 사실과 다르거나 읽기 어렵다 | 다크 테마에서 틀린 색, 실패가 빈 목록처럼 보임, 긴 이름이 옆 칸을 밀어냄, 잘린 결과에 표시가 없음, 비활성 이유 없음, iOS 에서 입력 확대 |
| 다듬기 | 일관성과 완성도 | 하드코딩된 전환 길이, 퇴장 모션 없음, 문구 형식 불일치, 모서리 반경 불일치 |

같은 규칙이라도 결과에 따라 단계가 달라진다. 하드코딩된 색은 보통 다듬기지만 다크 테마에서 글자가 보이지 않으면 틀림이다. 단계는 사용자에게 일어나는 일로 정한다.

배치 문제(주 동작이 묻혀 있음, 한 줄에 컨트롤이 몰려 있음)는 이 표로 매기지 않는다. [layout.md](layout.md) 의 신호로 따로 판정하고 보고의 별도 절에 적는다.

## 검색으로 찾는 것

패턴은 출발점이다. 프로젝트의 파일 확장자와 이름에 맞춰 고친다. 검색은 `rg` 를 쓴다.

| 찾는 것 | 패턴 | 확인할 것 |
|---|---|---|
| 하드코딩 색 | `rg -n "#[0-9a-fA-F]{3,8}\b\|rgba?\(" -g '*.{css,svelte,vue,tsx,jsx}'` | 토큰 정의 블록 밖의 것만. 다크 값이 따로 있는지 |
| 토큰 폴백 | `rg -n "var\(--[a-z-]+,\s*#"` | |
| 하드코딩 전환 | `rg -n "transition:[^;]*\b[0-9.]+m?s\b"` , `rg -n "transition:\s*all"` | 길이 토큰을 쓰는지 |
| 한글 조합 검사 누락 | `rg -n "key === '(Enter\|Escape)'\|keyCode === (13\|27)"` | 같은 핸들러에 `isComposing` 이 있는지. Ctrl 조합만 받는 핸들러는 제외 |
| 창마다 따로 쓴 닫기 | `rg -n "target === e\.currentTarget\|key === 'Escape'"` | 공용 수단을 거치는지, 몇 곳에 흩어져 있는지 |
| 이름 없는 아이콘 단추 | 아이콘만 든 `<button>` 을 찾아 `aria-label` 유무 확인 | 프레임워크마다 패턴이 다르니 아이콘 컴포넌트 이름으로 찾는다 |
| 네이티브 `title` | `rg -n "\btitle=" -g '!*.md'` | 꼭 필요한 정보(오류, 비활성 이유, 잘린 값)가 `title` 에만 있는지 |
| 비활성 호버 | `rg -n ":hover\s*\{" ` 중 `button`·`.btn` 대상 | `:not(:disabled)` 가 있는지 |
| 포커스 링 제거 | `rg -n "outline:\s*(none\|0)"` | 대신 그리는 링이 있는지 |
| 호버 전용 표시 | `rg -n ":hover [^{]*\{[^}]*opacity:\s*1"` | `:focus-within` 과 `hover: none` 대응이 있는지 |
| 작은 입력 글자 | 입력 요소의 `font-size` 가 16px 미만인 곳 | `pointer: coarse` 에서 16px 로 올리는지 |
| 화면 높이 | `rg -n "100vh"` | `100dvh` 를 덧썼는지 |
| 모션 줄임 | `rg -n "prefers-reduced-motion"` | 하나도 없으면 발견. `@keyframes` 가 줄임 모드에서 꺼지는지 |
| 줄임표의 `min-width` | `rg -n "text-overflow:\s*ellipsis"` | flex 자식이면 `min-width: 0` 이 있는지 |
| 이모지·문자 아이콘 | `rg -n "[✕✖×☰⋯▶▼]\|[\x{1F300}-\x{1FAFF}]"` | 단추·라벨 안의 것만 |
| HTML 삽입 | `rg -n "innerHTML\|\{@html\|dangerouslySetInnerHTML\|v-html"` | 넣는 값이 이스케이프를 거치는지 |
| 상태 알림 영역 | `rg -n "role=\"(status\|alert)\"\|aria-live"` | 진행·오류 안내에 붙어 있는지 |
| 확인창 남용 | `rg -n "confirm\("` | 되돌릴 수 있는 동작에 확인을 받는지 |
| 저장소 예외 처리 | `rg -n "localStorage\.\|indexedDB"` | `try` 로 감쌌는지 |
| 명사형 오류 문구 | `rg -n "실패[:：]\|오류[:：]\|Error:"` | 화면에 나가는 문구만 |

## 직접 해 볼 조작

화면을 띄워서 한다. 띄우지 못했으면 같은 경로를 코드로 따라가고 확인 수준을 낮춰 적는다.

| 조작 | 보는 것 | 해당 규칙 |
|---|---|---|
| 마우스 없이 Tab·방향키·Enter·Esc 로 주 작업을 처음부터 끝까지 한다 | 닿지 못하는 기능, 보이지 않는 포커스 | §4 |
| 창을 열고 Tab 을 계속 누른다. 닫는다 | 포커스가 창 안에서 도는지, 닫은 뒤 연 곳으로 돌아오는지 | §3 |
| 창 위에 확인창을 띄우고 Esc 를 한 번 누른다 | 맨 위만 닫히는지 | §3 |
| 입력창에 한글을 조합하는 중에 Enter·Esc 를 누른다 | 조합만 끝나는지 | §4 |
| 창의 입력에서 글자를 끌어 창 밖에서 놓는다 | 창이 닫히지 않는지 | §3 |
| 입력을 쓰다가 새로 고친다. 샘플·파일을 불러온다 | 쓰던 것을 되찾을 수 있는지 | §8 |
| 네트워크를 끊거나 실패를 유도한다 | 실패가 빈 상태와 구분되는지, 다시 시도할 수 있는지 | §5 |
| 100자 넘는 이름, 수백 개 항목, 아주 긴 오류 문구를 넣는다 | 줄임표, 스크롤, 밀림 | §11 |
| 폭을 360px 로 줄이고 터치 모드로 본다 | 모든 기능에 닿는지, 입력을 눌렀을 때 확대되는지, 호버 전용 단추가 보이는지 | §11 |
| 다크 테마로 바꾸고 모든 팝업·서드파티 위젯을 연다 | 틀린 색 | §1 |
| 시스템에서 모션 줄이기를 켠다 | 동작이 같은지, 스피너는 도는지 | §12 |
| 되돌릴 수 없는 동작의 확인창에서 바로 Enter 를 누른다 | 실행되지 않는지 | §7 |
| 빠르게 연타하고, 실행 중에 입력을 바꾼다 | 요청이 겹치지 않는지, 마지막 입력의 결과가 남는지 | §9 |

## 보고 형식

발견은 심각도 순으로, 같은 단계 안에서는 영향 범위가 넓은 순으로 적는다. 묶음 하나의 구성은 다음과 같다.

```markdown
### [막힘] 창마다 닫기 처리가 따로 있어 겹친 창이 Esc 한 번에 모두 닫힌다
- 위치: src/Settings.svelte:42, src/History.svelte:88, 외 5곳
- 근거: 각 창이 window 의 keydown 에서 Escape 를 직접 처리한다. 맨 위 창인지 확인하지 않는다
- 확인 수준: 실행함 (설정 창 위에 확인창을 띄우고 Esc → 둘 다 닫힘)
- 고치는 방법: 공용 모달 수단 하나로 옮긴다 (SKILL.md §3, components.md 모달)
```

확인 수준은 셋 중 하나다.

- **실행함**: 화면에서 재현했다. 한 조작을 적는다.
- **코드로 확인함**: 실행하지 않았지만 코드 경로를 끝까지 따라가 결과가 확정된다.
- **코드만 읽음**: 그럴 가능성이 높지만 실행해야 확정된다.

보고 전체의 구성.

1. **요약**: 단계별 묶음 수와 가장 먼저 고칠 두세 가지.
2. **발견**: 위 형식의 묶음들.
3. **배치**: layout.md 의 신호에 걸린 것. 재배치가 필요한지에 대한 판단.
4. **의도된 예외**: 프로젝트가 문서로 정한, 이 스킬과 다른 결정. 영향이 있으면 함께 적는다.
5. **해당 없음**: 이 프로젝트에 없는 부품.
6. **확인하지 못한 것**: 보지 않은 화면, 띄우지 못해 건너뛴 조작.

건수를 늘리려고 발견을 쪼개지 않는다. 지킨 규칙을 길게 나열하지 않는다. 사용자가 보고에서 얻어야 하는 것은 무엇부터 고칠지다.
