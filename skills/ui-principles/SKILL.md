# UI 원칙

처음 만든 화면은 대개 마우스로 정상 경로를 한 번 지나갈 때만 완성돼 있다. 나중에 고치게 되는 것은 거의 같은 종류다. 키보드, 터치, 실패, 진행 중, 빈 상태, 겹친 창, 긴 내용, 새로 고침이 빠져 있다. 새 화면을 만들 때 아래를 처음부터 넣는다.

## 시작하기 전에

1. 프로젝트에 이미 있는 것을 찾는다. 토큰이 정의된 전역 CSS, 공용 컴포넌트, 모달·툴팁·토스트·확인창을 띄우는 함수, 규칙 문서(`AGENTS.md`, `CLAUDE.md`, `DESIGN.md`)를 본다. 있는 것을 쓰고 같은 것을 다시 만들지 않는다.
2. 없으면 첫 번째 사용처에서 공용으로 만든다. 출발점이 필요하면 참고 문서를 읽는다.
   - [references/foundations.md](references/foundations.md): 토큰 구성, 테마, 글꼴, 포커스 링, 모션 토큰. 새 프로젝트를 시작하거나 토큰을 정리할 때 읽는다.
   - [references/components.md](references/components.md): 모달, 서랍, 메뉴, 툴팁, 토스트, 탭, 데이터 표, 분할선, 접이식 패널, 파일 드롭, 진행 표시의 세부 규칙과 코드 조각. 해당 부품을 만들 때 그 절만 읽는다.
   - [references/layout.md](references/layout.md): 배치를 정하는 순서, 모달·탭·서랍·접기 중 고르는 기준, 재배치가 필요하다는 신호. 새 화면의 배치를 정할 때, **기존 화면에 컨트롤을 더할 때**, 재설계할 때 읽는다.
3. 프로젝트의 기존 규칙이 이 문서와 다르면 프로젝트 규칙을 따르고, 다른 점을 보고에 적는다.

## 하는 일에 따라

- **새로 만들거나 고친다**: 아래 원칙을 따르고 끝에 "마치기 전 점검"을 한다.
- **기존 화면에 기능을 더한다**: 컨트롤을 놓기 전에 layout.md 의 "기능을 더할 때"를 본다. 빈자리에 붙이는 것이 가장 쉽지만 그렇게 쌓인 화면이 재설계 대상이 된다.
- **이미 만든 화면을 감사한다**: [references/audit.md](references/audit.md) 의 절차를 따른다. 심각도, 확인 방법, 보고 형식이 거기 있다. 감사 중에는 고치지 않는다.

## 1. 같은 것은 한 곳에서 정한다

- 색·그림자·포커스 링·전환 길이·이징·글꼴은 토큰(CSS 변수)만 쓴다. 컴포넌트에 `#c0392b`, `0.15s` 를 직접 쓰지 않는다. 새 색이 필요하면 토큰을 먼저 추가한다. `var(--danger, #c0392b)` 같은 폴백도 붙이지 않는다. 폴백은 다크 테마에서 틀린 색으로 남는다.
- 반투명 변형은 `color-mix(in srgb, var(--accent) 16%, transparent)` 처럼 토큰에서 만든다.
- 모달의 닫기·포커스 처리, 툴팁, 컨텍스트 메뉴, 스위치, 확인창, 토스트, 선택 막대는 화면마다 다시 쓰지 않는다. 두 번째 화면에 같은 CSS 나 핸들러를 복사하려는 순간이 공용으로 올릴 때다.
- 서드파티 위젯(코드 편집기, 문서 편집기, 날짜 선택기)의 색·글꼴·그림자·모서리도 앱 토큰으로 덮는다. 본체만 보지 말고 위젯이 띄우는 팝업, 선택 표시, 검색 창까지 하나씩 확인한다. 기본 테마는 다크에서 틀리기 쉽다.
- 아이콘은 한 세트에서 가져온다. 이모지나 `✕` 문자를 아이콘으로 쓰지 않는다.

## 2. 화면 구성과 위계

배치를 정하는 방법은 layout.md 에 있다. 여기는 결과가 지켜야 할 것이다.

- 컨트롤은 구현의 옵션 순서가 아니라 사용자가 일하는 순서와 쓰는 빈도로 놓는다. 매번 쓰는 것만 항상 보이는 자리에 둔다.
- 주 작업의 입력을 모달 안에 두지 않는다. 모달은 잠깐 끼어드는 확인과 짧은 입력에만 쓴다.
- **한 화면에 강조색으로 채운 단추는 하나다.** 그 화면의 주 동작에만 쓴다. 닫기·취소·보조 동작은 테두리 단추나 투명 단추로 둔다.
- 동작은 대상 옆에 둔다. 입력을 다루는 단추는 입력 영역에, 결과를 다루는 단추(복사, 내려받기)는 결과 영역에 둔다. 전역 동작(테마, 이력, 도움말)만 상단 바에 둔다.
- 자주 쓰지 않는 설정은 접어 둔다. 접힌 상태에서도 지금 켜진 값이 요약으로 보여야 한다.
- 부가 기능(이력, 참고 자료, 설정)은 새 페이지로 보내지 않고 서랍이나 옆 패널에 둔다. 작업하던 맥락이 화면에 남아야 한다.
- 구획은 면(배경 단계)과 1px 선으로 나눈다. 모서리가 둥근 요소에 한 변만 굵은 색 테두리를 주지 않는다. 선택 상태는 네 변 테두리나 배경으로 나타내고, 밑줄 표시는 탭 줄에만 쓴다.
- 숫자가 바뀌거나 세로로 늘어서는 곳(개수, 크기, 시각, 걸린 시간)은 `font-variant-numeric: tabular-nums` 를 준다.

## 3. 모달과 서랍

- **닫는 길은 우상단 X 와 Esc 로 통일한다.**
- Esc 와 Tab 은 맨 위 창만 받는다. 창 안의 단축키도 그 창이 맨 위일 때만 동작한다.
- 열리면 포커스를 창 안의 첫 입력(없으면 첫 동작 단추)에 준다. X 단추에는 주지 않는다. Tab 은 창 안에서만 돈다. 닫히면 창을 연 요소로 포커스를 돌려준다. 그 요소가 사라졌거나 그사이 다른 곳이 포커스를 가져갔으면 그대로 둔다.
- 창 뒤의 화면은 `inert` 로 막는다. 토스트와 툴팁은 막지 않는다.
- 바깥 클릭으로 닫을 때는 누른 지점과 뗀 지점이 둘 다 배경이어야 한다. 입력창에서 글자를 끌다가 창 밖에서 놓았을 때 닫히면 안 된다.
- 사용자가 입력한 내용이 있으면 X·Esc·바깥 클릭·취소 모두 "버리고 닫을까요?" 를 거친다. 미리 채워 준 값 그대로면 묻지 않는다.
- 처리 중에는 닫기를 막고 X 도 비활성으로 보인다.
- 창에는 `role="dialog"`, `aria-modal="true"` 를 주고 이름은 제목 요소를 `aria-labelledby` 로 가리킨다.
- 직접 구현할 이유가 없으면 네이티브 `<dialog>` 의 `showModal()` 을 쓴다. Esc, 포커스 복귀, 배경 막기를 브라우저가 맡는다.

## 4. 키보드

마우스로 되는 일은 키보드로도 되어야 한다. 끌어 놓기에는 "이동…" 같은 대체 경로를 함께 만든다.

- **한글 조합 중의 키는 무시한다.** Enter·Esc·방향키를 처리하는 모든 핸들러 첫 줄에서 `e.isComposing`(필요하면 `keyCode === 229`)을 확인한다.
- 메뉴·팝업 목록: ↑↓ 는 끝에서 돌아가고 Home/End 가 된다. 비활성 항목은 건너뛴다. 열면 첫 항목에 포커스를 준다. Esc 는 닫고 연 요소로 포커스를 돌려준다. Tab 은 닫는다.
- 목록·트리·탭·라디오 묶음은 Tab 정지점을 하나만 둔다(롤빙 tabindex). 안에서는 방향키로 움직인다. 행 안의 보조 단추는 `tabindex="-1"` 로 두고 메뉴 키(Shift+F10)로 닿게 한다.
- 관례 키를 지킨다. F2 이름 변경, Delete 삭제, Enter 열기·확정, Ctrl/⌘+Enter 는 여러 줄 입력의 완료·실행, Ctrl+A 전체 선택, Shift+방향키 범위 선택, F1 도움말.
- **Esc 는 가장 안쪽 것부터 한 단계씩 푼다.** 검색어 지우기 → 선택 해제 → 선택 모드 종료 → 창 닫기 순서다. 한 단계를 처리했으면 전파를 막는다.
- 포커스 복귀: 키보드로 끝낸 동작(Enter·Esc)만 원래 요소로 포커스를 돌린다. 마우스로 바깥을 눌러 끝났으면 그 클릭이 정한 포커스를 따른다. 포커스를 가진 항목이 삭제되면 이웃 항목으로 옮긴다. 포커스가 `body` 로 떨어지게 두지 않는다.
- 글자 한 개짜리 단축키(`?` 등)는 입력창 안에서는 동작하지 않게 한다.
- 입력창에 포커스가 있는 채로 눌러야 하는 보조 단추(기호 입력 줄, 접힌 설정의 요약)는 `pointerdown` 에서 `preventDefault` 해서 포커스를 빼앗지 않는다. 모바일에서 키보드가 내려가지 않는다.
- 단축키는 사용자가 볼 수 있는 곳에 적는다. 툴팁에 `닫기 (Esc)` 처럼 병기하고, 여러 줄 입력에는 `Enter 저장 · Esc 취소` 힌트를 보이고, 전체 목록은 앱 안의 도움말에 둔다.

## 5. 상태를 빠짐없이 그린다

| 상태 | 규칙 |
|---|---|
| 호버 | `:hover:not(:disabled)` 로 쓴다. 비활성 요소가 호버에 반응하면 안 된다. |
| 포커스 | `:focus-visible` 에 공통 링. `button` 만이 아니라 `a`, `select`, `textarea`, `[tabindex='0']` 에도 건다. 입력창은 테두리 강조색 + 바깥 링. |
| 눌림 | 아이콘 단추와 일반 단추만 살짝 줄어든다. 폭이 넓은 행·메뉴 항목은 제외한다. |
| 선택 | 호버, 지금 열린 항목, 고른 항목이 서로 구분돼야 한다. 배경·윤곽·굵기를 나눠 쓴다. |
| 비활성 | 흐리게만 두지 않고 이유를 툴팁이나 옆 글자로 말한다. 예: "읽기 모드에서는 바꿀 수 없습니다". |
| 진행 중 | 단추를 비활성으로 하고 라벨이나 아이콘을 바꾼다("바꾸는 중…"). 같은 요청이 두 번 나가지 않게 한다. |
| 낡음 | 입력이나 설정이 바뀌어 화면의 결과가 더는 맞지 않으면 그렇다고 표시하고, 다시 실행하는 단추를 눈에 띄게 한다. |
| 호버 전용 컨트롤 | 호버로만 나타나는 단추는 `:focus-within` 에서도 나타나고, 터치(`hover: none`)와 좁은 화면에서는 항상 보인다. |

- 색만으로 상태를 구분하지 않는다. 선 모양·아이콘·글자를 함께 쓴다. 임계값을 넘으면 색이 바뀌는 게이지에는 한계값을 글자로도 적는다.
- **꼭 알아야 하는 정보를 호버에만 두지 않는다.** 터치와 키보드로는 볼 수 없다. 오류 메시지, 잘린 값의 전체 내용, 비활성 이유는 호버 없이 닿는 경로가 있어야 한다.
- 데이터를 불러오는 화면은 **불러오는 중 / 실패 / 비어 있음 / 결과 있음** 네 가지를 각각 다른 문장으로 그린다. 실패에는 "다시 시도" 단추를 둔다. 비어 있음에는 무엇을 하면 채워지는지 쓴다. "항목이 없음"과 "검색 결과가 없음"은 다른 문장이다. 연결 실패를 빈 목록처럼 보이게 하지 않는다.
- 처음 쓰는 사람에게는 긴 안내문 대신 바로 넣어 볼 예시(샘플 불러오기)를 준다.

## 6. 결과를 알리는 방법

- 한 번 지나가는 일은 토스트로 알린다. 오류 토스트는 아이콘이 붙고 더 오래 머물며, 마우스를 올린 동안 사라지지 않고, 누르면 닫힌다. 동시에 쌓이는 수에 상한을 둔다.
- **계속되는 문제는 계속 보이는 표시로 알린다.** 저장 실패나 결과에 붙은 경고처럼 사용자가 조치해야 끝나는 것은 토스트 한 번으로 끝내지 않는다. 해결될 때까지 남는 배지나 칩에 조치 단추를 붙인다. 주의를 끄는 효과는 내용이 달라졌을 때만 낸다.
- 금방 끝나는 일에는 로딩 표시를 띄우지 않는다. 약 150ms 를 넘길 때만 띄운다. 번쩍였다 사라지는 스피너는 느리다는 인상만 남긴다.
- 복사처럼 화면이 바뀌지 않는 동작은 누른 단추에서 성공을 확인시킨다. 아이콘이 잠깐 체크로 바뀐다.
- 대화상자 안의 성공·오류는 스크롤 영역 밖의 고정 자리에 보인다. 새 작업을 시작하면 이전 안내를 지운다.
- 여러 건 중 일부만 실패하면 몇 건이 됐고 몇 건이 안 됐는지, 첫 번째 이유가 무엇인지 알린다. 전부 성공해서 화면이 바뀌었으면 따로 알리지 않는다.
- 결과가 상한에서 잘렸으면 잘렸다고 표시한다(`50+`, "이후 행은 표시하지 않음"). 오래된 기록을 자동으로 정리했으면 처음 한 번은 알린다.
- 사용자가 고쳐야 하는 오류는 상자로 풀어 쓴다. 순서는 무엇이 잘못됐는지 → 왜 그런지 → 어떻게 고치는지(비슷한 후보 제안) → 원문 오류다. 원문은 지우지 않고 작게 남긴다. 오류가 난 자리로 가는 단추를 둔다.
- 스크린 리더: 진행 안내는 `role="status"`, 오류는 `role="alert"`. 이 영역은 내용이 없을 때도 DOM 에 있어야 바뀐 내용을 읽어 준다.

## 7. 되돌릴 수 없는 동작

- **되돌릴 수 있으면 묻지 않는다.** 삭제는 휴지통으로 보내고 "되돌리기" 단추가 달린 토스트를 띄운다. 닫은 탭은 다시 열 수 있게 한다. 확인창은 사용자가 읽지 않고 누르게 될 뿐이다.
- 되돌릴 수 없는 동작만 확인을 받는다. 문구에 대상과 규모를 쓴다("항목 3개(글 12개)가 완전히 삭제되며 되돌릴 수 없습니다"). 확정 단추는 위험색으로 채우고 라벨은 동사다("삭제", "비우기"). **처음 포커스는 취소에 둔다.** Enter 한 번으로 실행되면 안 된다.
- 넓은 범위를 바꾸는 동작(전체 바꾸기)은 실행 전에 몇 곳이 바뀌는지 세어 보여 주고, 이전 내용이 어디에 남는지 말한다.
- 목록 행마다 반복되는 삭제 단추는 평소 중립색이고 호버에서만 위험색이 된다. 메뉴에서 위험 항목은 맨 아래, 구분선 뒤에 둔다.

## 8. 작업물을 잃지 않게 한다

- 사용자가 쓴 내용은 "저장할까요?" 를 묻지 않고 자동으로 저장하고, 새로 고침하면 되살린다. 자동 저장할 수 없는 구조일 때만 떠나기 전에 경고한다.
- **입력을 통째로 바꾸기 직전에 지금 내용을 먼저 보존한다.** 샘플 불러오기, 파일 열기, 이력 복원, 비우기가 모두 해당한다. 가능하면 덮어쓰지 않고 뒤에 덧붙인다.
- 자동으로 쌓는 이력은 타이핑 중간 상태로 채우지 않는다. 짧은 시간 안의 연속 저장은 직전 항목을 갈아 끼우고, 같은 내용은 한 건으로 합친다.
- 화면 설정(패널 크기, 접힘, 탭, 테마, 스위치 값)은 조작이 끝나는 순간 저장한다. 되살릴 때는 값을 검증한다.
- 저장소를 쓸 수 없어도 앱은 동작해야 한다. 저장소 접근은 예외를 잡고 메모리로 내려간다. 너무 커서 저장하지 못했으면 이유를 알린다.
- 탭이 숨겨지거나 닫힐 때(`visibilitychange`, `pagehide`) 미룬 저장을 바로 실행한다. 창이 다시 포커스를 받으면 다른 탭에서 바뀐 내용을 다시 읽는다.
- 테마는 첫 화면이 그려지기 전에 정한다. 늦으면 밝은 화면이 번쩍인다.

## 9. 자동 실행과 입력 중 검사

- 디바운스 길이는 입력의 종류에 맞춘다. 목록 걸러내기는 120~200ms, 무거운 변환·검사는 400~600ms, 붙여넣기와 설정 변경은 거의 바로 실행한다.
- 입력 중인 값과 적용된 값을 나눈다. Enter 와 지우기 단추, 수동 실행 단추는 기다리지 않고 바로 적용하며 대기 중인 자동 실행을 취소한다.
- 한 번에 하나만 실행한다. 실행 중에 들어온 요청은 끝난 뒤 최신 입력으로 한 번만 다시 돈다. 응답이 늦게 온 이전 요청은 버린다.
- **자동 실행은 조용히, 사용자가 누른 실행은 확실히 알린다.** 완료 표시, 빈 입력 경고, 포커스 이동은 사용자가 직접 실행했을 때만 한다. 자동 실행이 실패하면 이전 결과를 남겨 둔다.
- 입력 중 검사는 지금 쓰고 있는 자리의 오류를 가장 늦게 보인다(1~1.5초). 문장을 쓰는 도중에 빨간 줄이 번쩍이면 안 된다. 다른 자리의 오류는 바로 보인다. 싼 검사와 비싼 검사의 지연을 나눈다.
- 자동 실행은 사용자가 끌 수 있고, 그 선택을 기억한다.

## 10. 목록·선택·끌어 놓기

- 다중 선택 규칙은 앱 전체에서 같다. Ctrl/⌘+클릭 토글, Shift+클릭 범위, 터치용 선택 모드(행마다 체크박스). 일반 클릭은 선택을 풀고 연다.
- 선택이 생기면 일괄 작업 막대가 나타난다. 구성은 "N개 선택 · 작업 단추들 · 위험 작업 · 선택 해제" 순서다. 메뉴 항목 라벨에도 개수를 넣는다("3개 이동…").
- 상위 항목과 그 안의 항목을 함께 골랐으면 상위만 대상으로 삼는다. 화면에서 사라진 항목은 선택에서 뺀다.
- 끌어 놓기는 놓았을 때 일어날 일을 놓기 전에 보여 준다. 여러 개를 끌면 개수 배지를 단다. 선만으로 알 수 없는 결과는 글로 알린다. 놓을 수 없는 곳은 금지 커서로 둔다. 접힌 폴더 위에 머물면 펼친다.
- 파일을 끌어 오면 놓을 자리를 표시한다. 받을 곳이 하나면 화면 전체에, 여럿이면 영역마다 표시한다. 받는 형식을 함께 적는다. 파일이 아닌 끌기(글자 선택)에는 반응하지 않는다. 영역 밖에 놓았을 때 브라우저가 그 파일로 이동하지 않게 막는다.
- 파일 열기 단추, 붙여넣기, 끌어 놓기는 같은 함수로 들어간다. 검사와 안내가 한 곳에 있어야 한다.
- 컨텍스트 메뉴는 우클릭, 길게 누르기, 메뉴 키, 행의 ⋯ 단추가 같은 메뉴를 연다. 항목 순서는 만들기 → 고치기 → 옮기기 → 내보내기 → 위험 동작이다.

## 11. 레이아웃·넘침·좁은 화면

실제 내용은 예시보다 길다. 긴 파일 이름, 긴 오류 문구, 수백 개의 항목을 넣어 본다.

- 한 줄로 자를 글자: `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`. flex 자식이면 `min-width: 0` 을 함께 준다. 빠뜨리면 줄임표가 생기지 않고 옆 칸을 밀어낸다.
- 경로·URL·오류 문구처럼 끊을 곳이 없는 글자: `overflow-wrap: anywhere`.
- 목록은 `max-height` 와 `overflow: auto` 를 준다. 높이가 고정된 영역에서 내용이 잘렸으면 하단을 흐리게 해서 더 있음을 알린다. 항목이 아주 많으면 상한을 두고 "더 보기"로 나눈다.
- 떠 있는 요소의 크기는 `min(420px, calc(100vw - 32px))`, `max-height: calc(100dvh - 32px)` 처럼 화면을 넘지 않게 한다. 위치는 화면 안으로 당기고, 아래 공간이 모자라면 위로 뒤집는다.
- 좁은 화면 기준 폭은 프로젝트에서 하나만 정한다. 터치 대응은 폭이 아니라 입력 방식으로 건다: `@media (pointer: coarse), (max-width: <기준>)`.
- **터치에서 입력창 글자는 16px 이상이다.** 그보다 작으면 iOS 가 화면을 확대한다. 누르는 영역은 36px 이상으로 키운다.
- 좁은 화면에서는 좌우 분할을 위아래로 쌓고, 사이드바는 밀려 나오는 패널로 바꾸고, 크기 조절 손잡이는 없앤다. 덜 중요한 것부터 숨기되 다른 경로(메뉴, 명령 팔레트)를 남긴다. 단축키 힌트는 숨긴다.
- 높이는 `100vh` 뒤에 `100dvh` 를 덧쓴다. 가장자리 여백에는 `env(safe-area-inset-*)` 를 더한다. 화면 키보드가 올라와도 입력 중인 곳이 보여야 한다.
- 떠 있는 층은 그림자 단계로 구분한다. 단추·카드에는 얕은 것, 팝오버·서랍·대화상자에는 깊은 것을 쓴다.

## 12. 모션

모션은 무엇이 어디서 나타나고 어디로 사라졌는지 알려 주는 용도로만 쓴다.

- 길이는 토큰 두세 단계로 정한다. 색·테두리 같은 상태 변화는 짧게(120~130ms), 크기·위치 변화는 길게(180~260ms). 이징은 기본 ease-out, 튀는 느낌이 필요한 손잡이·팝오버에만 spring 을 쓴다.
- 나타나는 요소에는 등장과 퇴장을 함께 준다. 퇴장은 등장보다 짧게 한다. 갑자기 사라지는 것도 결함이다.
- 목록에서 항목이 빠지거나 끼어들면 남은 항목이 미끄러져 자리를 잡는다. 순차 등장의 지연에는 상한을 두고, 항목이 많으면 효과를 끈다.
- `prefers-reduced-motion` 을 모든 모션이 따른다. 이동·확대를 빼고 투명도만 남기거나 길이를 0 에 가깝게 줄인다. **스피너와 진행 막대는 줄임 모드에서도 움직인다.** 멈추면 멈춘 것처럼 보인다.
- 고정 위치 자손(팝오버·툴팁)이 있는 영역에는 `transform` 을 쓰지 않는다. 기준점이 바뀌어 자손의 위치가 틀어진다. 투명도만 쓰거나 `translate`·`scale` 개별 속성을 쓴다.

## 13. 화면 문구

- 오류는 "무엇을 하지 못했는지: 이유" 형식의 문장으로 쓴다. `내보내기 실패: …` 대신 `백업 파일을 만들지 못했습니다: …`. 이유 끝에 마침표를 붙이지 않는다.
- 성공 안내에는 대상 이름이나 건수를 넣는다("추가 3, 중복 1, 제외 2").
- 진행 중 문구는 `연결을 확인하는 중…` 처럼 조사까지 쓴다.
- 단추 라벨은 동사다. "확인" 대신 그 단추가 하는 일을 쓴다("삭제", "바꾸기", "버리기").
- 말줄임표(`…`)는 누른 뒤 입력이나 선택이 이어지는 항목에만 공백 없이 붙인다("이동…", "파일 선택…").
- 목록 항목의 부가 정보는 가운뎃점으로 잇는다(`오늘 14:20 · 120줄 · 8KB`). 오늘의 시각은 날짜를 빼고, 올해의 날짜는 연도를 뺀다.
- 설정의 설명은 조작에 맞춘다. 스위치면 "켜면 …" 이라고 쓴다. 켜짐/꺼짐은 스위치, 여러 개 중 고르기는 체크박스다.
- 사용자가 다른 도구의 용어로 틀렸으면 이쪽 용어를 대응해서 알려 준다.

## 14. 접근성 표기

- 아이콘만 있는 단추에는 `aria-label` 과 툴팁을 둘 다 붙인다. 행 안의 단추는 라벨에 대상 이름을 넣는다("보고서 메뉴").
- 토글 단추는 `aria-pressed`, 스위치는 `role="switch"` + `aria-checked`(또는 네이티브 체크박스), 접기 단추는 `aria-expanded`, 메뉴·서랍을 여는 단추는 `aria-haspopup`/`aria-controls`.
- 트리·탭·라디오 묶음·메뉴·분할선(`role="separator"`)은 WAI-ARIA 패턴의 role 과 키 규칙을 그대로 따른다.
- 장식(점 배지, 막대 그래프, 단축키 힌트)은 `aria-hidden` 으로 가리고, 뜻이 있는 것은 화면 밖 글자(`.sr-only`)로 대신 전한다. CSS `content` 로 넣은 글자는 읽히지 않을 수 있으니 뜻이 있는 글자는 DOM 에 둔다.
- 접혀서 보이지 않는 영역은 `inert` 나 `visibility: hidden` 으로 Tab 순서에서 뺀다.
- 툴팁은 터치에서 띄우지 않는다. 키보드 포커스에서는 `:focus-visible` 일 때만 띄운다.
- 사용자 입력과 외부 데이터는 텍스트로 넣는다. HTML 로 넣어야 하면 이스케이프를 거친 문자열만 넣는다.

## 마치기 전 점검

화면을 만들었거나 고쳤으면 다음을 직접 해 보거나 코드로 확인한다. 하지 못한 항목은 보고에 적는다.

1. 마우스 없이 Tab·방향키·Enter·Esc 만으로 열고, 쓰고, 닫을 수 있는가. 닫은 뒤 포커스가 연 곳으로 돌아오는가.
2. 한글을 조합하는 중에 Enter·Esc 를 눌러도 엉뚱한 동작이 나지 않는가.
3. 다른 창 위에 겹쳐 띄웠을 때 Esc 가 맨 위 창만 닫는가.
4. 불러오는 중, 실패, 비어 있음을 각각 볼 수 있는가. 실패에서 다시 시도할 수 있는가.
5. 아주 긴 이름과 수백 개의 항목을 넣어도 레이아웃이 깨지지 않는가.
6. 좁은 폭과 터치에서 모든 기능에 닿을 수 있는가. 입력창을 눌렀을 때 화면이 확대되지 않는가.
7. 다크 테마에서 색이 맞는가. 서드파티 위젯의 팝업도 맞는가. 컴포넌트에 직접 쓴 색·시간 값이 없는가.
8. 애니메이션을 줄인 상태에서도 동작이 같은가.
9. 되돌릴 수 없는 동작이 Enter 한 번으로 실행되지 않는가.
10. 쓰던 중에 새로 고침하거나 다른 내용을 불러와도 쓰던 것을 되찾을 수 있는가.
11. 화면에 강조색으로 채운 단추가 하나뿐인가.
